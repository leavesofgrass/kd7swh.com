# Editorial standard — the Linux User Net weekly links

**The test:** Does this change what a Linux user or a radio operator can
**do**, or should **do**? And is there something here to **discuss**, not just
announce? Two noes and it does not run.

**Excluded by default:**

- **Point releases and patch-level updates.** "Debian 13.6 ships security fixes."
  Everyone's update manager already handled it. *This is the specific failure
  mode Jon has been seeing — the exclusion is not theoretical.*
- **CVE and security-flaw disclosures.** Reading CVE numbers on the air is noise.
- **"Distro X version Y is out"** absent a landscape change — dropped hardware
  support, a governance split, a reverted migration, a licensing change. If the
  release *is* the story, cut it. Do not demote it. Cut it.
- **Unshipped or speculative.** Not merged, not shipped, not committed to.
- **Aggregator rewrites of a press release.** Find the primary source or drop it.
- **Anything not personally opened and read.**

**Actively wanted:**

- Project direction changes, governance fights, community events
- Supply-chain incidents and anything changing how people should trust tooling
- New tools someone can install this week
- SDR, SBCs, microcontrollers, LoRa and Meshtastic, digital modes
- Hardware that changes the calculus for a shack or a bench
- Policy and regulation touching operators or open source

**Per-story verification before checking the box:** opened the article not the
snippet; publication date inside the window; headline matches the body; primary
source identified where secondhand; there is something to talk about.

**Do not pad to reach a count.** Nine good candidates beats twelve with three
version bumps.
